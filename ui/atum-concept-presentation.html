SLIDE 3 / 10 · CONCEPT 1: PARTITIONING A Atum Concept Guide

Concept 1: Identifying Any Dataset Slice ("Partitioning")

Because not every system uses a data catalog or updates daily, Atum identifies datasets by an ordered key-value map.

1. Ordered Key-Value Identity (Unique Slice ID)

An ordered list of (key, value) pairs. Any two submissions with the exact same ordered keys and values resolve to the same Partitioning ID:

#1 catalog_path = edla_curated.customer_payments
#2 info_date = 2026-11-11
2. Partitioning Metadata (Additional Context)

Extra key-value attributes attached to the partitioning to record technical or business context without changing its primary identity:

catalog_provider = aws-glue
join_keys = customer_id, country_code
Example A · Mainframe Feed
Daily Mainframe Extract

Mainframe feeds do not live in Glue or Hive, so they use system, feed, and date keys:

1. system = core_banking
2. feed = payments_eod
3. info_date = 2026-11-11
Example B · Ingestion & Curation
Daily Catalog Table

Ingestion and curation apps produce tables in Glue or Hive partitioned by logical date:

1. catalog_path = raw.core_payments
2. info_date = 2026-11-11
Example C · Reference Data
Quarterly Lookup Table

Infrequently updated reference datasets use a release version instead of a daily date:

1. catalog_path = ref.iso_countries
2. ref_version = 2026-Q4

How Measures Catch Row Drops vs. Silent Amount Edits

Row counts catch missing records, but financial sums are essential to catch silent numeric corruption when row counts stay equal.

Scenario A · Row Loss or Join Filter ⚠ Measure Shift

Row 5 (TX-105, guest with customer_id = null) is dropped during an inner join with the customer master table:

tx_idcustomer_idamount
TX-101CUST-011,000.00
TX-102CUST-022,500.00
TX-103CUST-01500.00
TX-104CUST-034,000.00
TX-105null (dropped)200.00
• count(*): 5 → 4 (−1 row caught)
• sum(amount): 8,200.00 → 8,000.00 (−200.00 caught)
• distinct(customer_id): 3 → 3 (All 3 known customers retained)
• hash(tx_id): #A9F4 → #7C12 (ID fingerprint shifted)
Scenario B · Silent Amount Alteration ⚠ Measure Shift

All 5 rows arrive and all tx_id keys are intact, but Row 2's amount is corrupted from 2,500.00 to 2,050.00:

tx_idcustomer_idamount
TX-101CUST-011,000.00
TX-102CUST-022,050.00 (was 2,500.00)
TX-103CUST-01500.00
TX-104CUST-034,000.00
TX-105null200.00
• count(*): 5 → 5 (Row count completely misses this!)
• hash(tx_id): #A9F4 → #A9F4 (All 5 transaction IDs arrived!)
• distinct(customer_id): 3 → 3
• sum(amount): 8,200.00 → 7,750.00 (−450.00 caught by Sum!)

How Measures Catch Key Swaps & Verify Rollups

Hash fingerprints detect substituted records even when totals match; sums verify aggregations when row grain changes.

SLIDE 7 / 10 · CONCEPT 4: CROSS-SYSTEM LINEAGE LINKING A Atum Concept Guide

Concept 4: Linking Lineage Across System Boundaries

Downstream systems reconstruct the upstream Partitioning keys at the integration boundary and register an explicit Parent → Child link.

A Spark Pipelines: Automated via Atum Agent
When a Spark job loads a catalog table, the embedded Atum Agent reconstructs the parent keys and links the child partitioning automatically.
B Non-Spark Systems: Direct REST API POST
Systems without Spark/Scala (Mainframe bridges, Python/SQL services) send an HTTP POST directly to Atum Server with their keys, parent keys, and checkpoints.

SLIDE 10 / 10 · CONSUMPTION & AUDIT MECHANISMS A Atum Concept Guide

How Analysts & Auditors Query Lineage & History

Three core query mechanisms power discovery, impact analysis, and historical trend verification.

1 Key & Time-Window Discovery

Find dataset runs by any subset of partitioning keys and a reproducible checkpoint time interval [from, to):

• All tables for a business date: keys = { info_date: "2026-11-11" }
• Reproducible audit window: from = 2026-11-04T00:00Z, to = 2026-11-11T23:59Z
2 Directional Lineage Graph Traversal

Start from any Partitioning ID and traverse the directed graph up to N hops:

• Upstream (Ancestors): "Where did this report come from?"
• Downstream (Descendants): "Which reports depend on this raw feed?"
3 The "Key-Drop" Mechanism for Historical Trend Comparison
